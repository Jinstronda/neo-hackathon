## 2026-11-20, cloud runner hardening (ws25)

- Merge gate decided entirely server-side from run events, never from a client claim: approve requires a proven pre-patch exploit (`flag_check phase=pre-patch objective_complete=true`), a green post-patch retest (`objective_complete=false`), the approver SET exactly `{security, correctness}` with no `request_changes`, and not-already-merged. Chose set-equality over `len(approvers)==2` so two approvals from one reviewer, or an approve-then-request_changes, cannot merge. Evidence: `console/ops/cloud_runner.py` merge_ready(); `qa/contract/test_cloud_runner.py` test_merge_gate. [certain, two-way]
- Scrub the whole served response, not only the harness error path: full auth-header lines (`[:=][^\r\n]*`), JWTs, private keys, quoted/bracketed `secret=` assignments, every env-sourced secret plus its base64 and url-encoded forms, and any value under a secret-named key. Chose breadth because the success-path blue_patch diff carries the weak-JWT demo secret, which the error-path-only scrub missed. Risk: a legitimate field named like a secret is redacted whole; none exist in the schema today. Evidence: scrub()/_redact(); test_scrub. [certain, two-way]
- Run-generation isolation: every event is stamped with `state["gen"]`, which rises on each attack; a late emit from a prior run's fix thread is dropped, gate reads only current-gen events, and attack refuses while a run is in flight. Chose stamping over clearing state because fix/review run on background threads that outlive a reset. Evidence: emit()/current()/attack(); test_gen_isolation. [certain, two-way]
- Fail-closed DoS fix: fix() and harness() release `fixing`/`running` in a `finally` (gen-guarded) and emit an error event on crash, instead of wedging the runner against every later attack. Evidence: run_fix()/harness() try-finally; test_fix_crash_releases_lock. [certain, two-way]
- Live-path field parity: the live engine run emits a `pr_number` derived deterministically from the patch digest (stable per patch, 1–90) plus `pr_url`, on blue_patch/review/merge, and mirrors `run.metrics` surface/cost figures onto the metrics event. Chose a derived PR number because the cloud runner opens no real GitHub PR; chose to mirror run.metrics (one source of truth) rather than hardcode or fabricate new figures. Assumption: showing the demo target's surface figures (83/17) as the live run's is accurate because it is the same app. Evidence: fix() pr_number/pr_url + metrics emit; contract ui-reads-exist PASS on a real box run. [assumed, two-way]
- Shipped on branch `ws25-runner-hardening`, deployed to the box by scp + `docker restart neo-runner`, but NOT merged to master. A master push auto-deploys the console to production, against the task's "previews only, never promote to production" constraint; the box runs the hardened code regardless of the git branch.
